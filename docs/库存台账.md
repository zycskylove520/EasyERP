# 库存台账

库存台账是 EasyERP 的存货账本：它把「当前还剩多少货」「我做过哪些库存变动」「每一次变动的细节」拆成三个页面，所有数量都由系统根据库存流水自动累计，不需要也不允许手工改写现有数字。

## 入口路径

左侧菜单「库存」分组下有三个页面：

| 页面 | 路由（地址栏 hash） | 前端视图 |
| --- | --- | --- |
| 当前库存 | `#/inventory` | InventoryView.vue |
| 库存调整 | `#/inventory/adjust` | InventoryAdjustView.vue |
| 库存流水 | `#/inventory/ledger` | InventoryLedgerView.vue |

应用是桌面单机版，数据保存在本机，没有云端同步；这三个页面只读取和追加库存流水，本身不直接修改业务单据。

## 一、当前库存（#/inventory）

用途：一屏查看所有货品的现存数量，是库存台账的「结果页」。

功能与操作：

1. 打开页面后系统自动加载全部货品，无需点击查询。
2. 表格共有四列：**货品**、**品类**、**当前数量**、**单位**。
3. 货品按编号顺序列出；即使某个货品从未有过任何库存流水，也会显示，数量为 0。
4. 数量为负数时（例如 -3），数字会显示为**红色**，提醒该货品已欠货。
5. 如果还没有建立任何货品档案，表格会显示「暂无货品」。

> 说明：当前版本的页面不提供品类筛选控件；后端接口 `GET /inventory/stock` 支持按 `categoryId` 过滤，但前端未使用该参数。

## 二、库存调整（#/inventory/adjust）

用途：设置期初库存，或记录盘点、损耗、补录等手工变动。

操作步骤：

1. 打开页面，系统自动加载货品下拉列表（显示「货品名称（品类）」）。
2. 在**操作**下拉框中选择一种模式：
   - **设置期初**：为新货品录入开始使用系统时的初始数量。
   - **手工调整**：记录一次库存增减。
3. 在**货品**下拉框中选择要处理的货品（必填）。
4. 填写数量（必填，允许负数）：
   - 期初模式下填「期初数量」；
   - 手工调整模式下填「增减数量」，**负数表示扣减库存**，正数表示增加。
5. 按需填写**备注**（例如「2026 年 1 月盘点」「报废 2 件」），备注会写入流水，便于日后追溯。
6. 点击**提交**。成功时页面顶部显示绿色提示「期初已设置」或「库存调整已记录」；失败时显示红色错误信息。
7. 提交成功后，数量和备注输入框会被清空（货品和操作模式保留），方便连续录入。

表单校验：货品必选、数量必须是数字；手工调整的数量不能为 0；期初数量每个货品只能设置一次，且必须在该货品产生任何流水之前完成。

## 三、库存流水（#/inventory/ledger）

用途：查询每一笔库存变动的明细，是库存台账的「过程页」。

筛选操作：

1. **货品**下拉框：默认「全部货品」，选定某个货品后只显示它的流水。
2. **原因**下拉框：默认「全部原因」，可按变动原因筛选。
3. 选择条件后列表自动刷新，也可点击**筛选**按钮手动刷新。
4. 列表按流水编号倒序排列，即**最新发生的记录在最上面**。

表格列：**时间**、**货品**、**变动**、**原因**、**备注**。

- 「变动」列：正数显示为绿色并带 `+` 号（如 `+20`），负数显示为红色（如 `-3`）。
- 「备注」为空时显示 `-`。

页面上可见的「原因」选项及含义：

| 原因（页面标签） | 含义 |
| --- | --- |
| 期初 | 设置期初库存 |
| 手工调整 | 在库存调整页手工录入的增减 |
| 送货扣减 | 送货单确认时按明细扣减库存 |
| 送货冲销 | 送货单打回时把扣减的数量还回 |
| 订购入库 | 订购单确认时按明细增加库存 |
| 订购冲销 | 订购单打回时把入库的数量减回 |
| 报价扣减(历史) | 旧版本报价单曾扣减库存（历史数据专用） |
| 报价冲销(历史) | 旧版本报价单打回时的冲销（历史数据专用） |

> 后两个「报价…(历史)」只是给老数据看的标签；当前版本创建报价单已不再产生库存流水，新系统中不会出现这类记录。

## 关键业务规则（数据是怎么算出来的）

1. **流水账模型，库存 = 流水求和。** 系统从不直接保存「当前库存」这个数字。`当前库存 = 该货品所有库存流水的变动量（delta）之和`；没有任何流水时按 0 计算。当前库存页、概览看板的库存总量、财务之外的所有库存口径都遵循这一条。
2. **流水只增不改。** 历史流水一旦写入就不能编辑或删除；发现录错只能用一条新的手工调整流水去抵消，这样账目始终可追溯。
3. **期初一次性。** 设置期初时，系统检查该货品是否已有任何流水；只要有流水（哪怕是一条手工调整）就拒绝再设期初，避免期初与后续变动打架。
4. **两种手工调整：**
   - 页面上的「手工调整」是**增量模式**：填 `+5` 就加 5，填 `-5` 就减 5，必须非 0。
   - 后端还提供「目标值模式」（`POST /inventory/set`，当前页面未使用）：直接把库存设为指定数量，系统自动计算 `差额 = 目标 − 当前`，再记一条手工调整流水；目标不能为负，差额为 0 时不产生流水。
5. **业务单据自动记账。** 确认订购单 → 按每条明细生成「订购入库」正流水（入库数量必须大于 0）；确认送货单 → 生成「送货扣减」负流水。整个过程在数据库事务中完成，要么全部记上，要么一条都不记。
6. **打回 = 反向冲销。** 订购单/送货单被打回（状态从「已确认」变为「已打回」）时，系统按原流水生成一条方向相反的冲销流水，并在冲销记录里标注原流水编号；同一条流水只能被冲销一次，重复打回会被拒绝。冲销后库存自动回到确认前的状态。
7. **允许负库存。** 扣减时不检查库存是否够用，库存可以被扣成负数。送货单/订购单确认时若发现余量小于 0，会向使用者返回补货提醒；这些货品也会出现在「概览」页的负库存预警表里，并在当前库存页标红。
8. **流水原因受系统约束。** 数据库层面只允许 6 种原因：期初、手工调整、送货扣减、送货冲销、订购入库、订购冲销；页面额外列出的两种「报价…(历史)」是为了兼容早期版本遗留的数据。

## 注意事项

- 期初请在使用任何其他库存功能之前设置；一旦货品有了流水就不能再补设期初，只能用手工调整把数量调到位。
- 库存调整会真实改变库存数量，进而影响送货单确认时的余量和概览看板；录入前请核对货品和正负号。
- 手工调整的「增减数量」不是「调整后的库存」，填错符号方向会相反。建议养成必填备注的习惯，方便在库存流水里定位。
- 库存不足不会阻止送货单确认，系统只提醒不拦截；请定期查看概览页的「负库存预警」。
- 库存流水按时间倒序展示，早期版本的报价扣减/冲销记录也会显示，但不会出现在新增原因中。
- 库存模块与业务单据紧密联动：想撤销一次入库或出库，正确做法是在业务单据页将单据「打回」，系统会自动冲销，而不是在库存流水里手动改数。
