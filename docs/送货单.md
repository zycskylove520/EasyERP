# 送货单

> 销售侧出库单据：记录实际送给客户的货品；草稿确认后按关联货品扣减库存，可从报价单带入明细，是库存减少的真正发生环节。

## 一、入口路径

左侧导航「业务单据」分组中选择「送货单」。应用使用 hash 路由，常见页面地址：

| 页面 | 路径 |
| --- | --- |
| 送货单列表 | `#/delivery-notes` |
| 新建送货单 | `#/delivery-notes/new` |
| 编辑送货单 | `#/delivery-notes/:id/edit` |
| 打印预览 | `#/delivery-notes/:id/print` |
| 打回单据列表 | `#/delivery-notes/rejected` |

列表页右上角有「+ 新建送货单」和「打回单据」按钮。列表可按单号、客户、日期区间筛选。

## 二、单据状态

- **草稿（DRAFT）**：新建或从报价单带入后的初始状态，可编辑、删除、确认；此时**不扣库存**。
- **已确认（CONFIRMED）**：点「确认」后状态，库存已扣减；不能再编辑或删除，只能「打回」。
- **已打回（REJECTED）**：打回后的历史单据，移入「打回单据」列表，可预览、导出、复制。

状态流转为单向：**草稿 → 已确认 → 已打回**。

## 三、单据字段说明

### 可选带入（表单顶部）

| 字段 | 说明 |
| --- | --- |
| 从报价单带入 | 下拉选择活跃的报价单，点「带入明细」后自动填入客户、订单号码和明细；带入后仍可自由修改 |

### 表头信息

| 字段 | 说明 |
| --- | --- |
| 客户 | 下拉选择；选中后带出「客户名称」和「收货地址」（地址仅在留空时带入一次） |
| 客户名称（快照，可改） | 打印显示的客户名，可手工修改 |
| 出货日期 | 默认当天 |
| 收货地址 | 打印在单据上 |
| 订单号码 | 可手填；从报价单带入时为报价单号；明细表里的订单号码列整单统一显示这个值 |
| 整单备注 | 打印/导出时显示在明细表下方，按行显示；留空则不显示 |

### 明细行

| 字段 | 说明 |
| --- | --- |
| 关联货品 | 下拉选择「销售」类货品；选中后带出品名、单位、规格值；确认时按此货品扣库 |
| 品名 | 可手改，必填 |
| 规格 | 点「填规格」展开，按该货品所属品类的规格字段填写；一张单可混装不同品类 |
| 单位 | 从货品带入，可改 |
| 数量 | 必填，不能为负数；确认时按此数量扣库 |
| 单价 | 必填，不能为负数 |
| 金额 | 自动计算 = 数量 × 单价，无需手填 |
| 备注 | 该行备注，打印在表格「备注」列 |

表单底部显示明细金额「合计」。

## 四、操作步骤

### 1. 手工新建

1. 列表页点「+ 新建送货单」。
2. 「从报价单带入」保持「不带入，手工填写」。
3. 选择客户，填出货日期、收货地址、订单号码、整单备注。
4. 点「+ 添加一行」，选关联货品，填数量、单价；需要时展开填规格。
5. 点「保存草稿」。校验规则：客户必填、每行品名必填、数量和单价必填且不为负。
6. 保存成功返回列表，状态为草稿。

单号自动生成，规则为 `前缀-YYYYMMDD-四位随机数`。前缀取自「公司基础信息」里配置的送货单号前缀（例如 `YLD`），未配置时默认 `DN`，例如 `YLD-20261123-4821`；重复时重新生成。

### 2. 从报价单带入新建

1. 新建页顶部「从报价单带入」下拉选择一张活跃报价单（显示为「报价单号 · 客户名」）。
2. 点「带入明细」，系统从该报价单读取客户、客户名称、报价单号（填入订单号码）、报价单 ID，以及全部明细（货品、规格、单位、数量、单价、备注）。
3. 带入后逐项核对、按需修改（客户、地址、数量、价格都可改），再点「保存草稿」。
4. 带入只预填数据、不改库存；原报价单也不受影响。

### 3. 编辑与删除

草稿行点「编辑」可修改后保存，点「删除」可删除（二次确认）。只有草稿支持编辑和删除。

### 4. 确认（扣库）

1. 草稿行点「确认」，弹窗提示「确认（将扣减库存）」，点确定。
2. 后端在事务内逐行处理：对每个关联了货品且数量大于 0 的明细，按数量扣减该货品库存（库存流水原因 `DELIVERY_CONSUME`），状态改为「已确认」。
3. 允许扣成负数（库存可以为负）。若有货品扣减后余量小于 0，确认后列表页顶部会弹出红色「库存不足提醒」，列出货品名和当前余量，提醒及时补货；点「关闭」可收起。
4. 扣库与状态变更在同一事务内完成，要么全部成功，要么全部不生效。

### 5. 打回（还库）

1. 已确认行点「打回」，弹窗提示「打回（将还回库存）」，点确定。
2. 后端在事务内把扣库流水反向冲销（库存流水原因 `DELIVERY_REVERSE`，数量为正，还回库存），状态改为「已打回」。
3. 冲销幂等：同一笔扣库流水只冲销一次，不会重复还库。
4. 打回单出现在「打回单据」列表，可预览、导出 Word/PDF、复制。

### 6. 复制

列表行（含打回单）点「复制」，生成一张新草稿：单号重新生成、出货日期改为当天，其余表头与明细原样带入，不复制库存流水引用。复制后跳到新草稿编辑页。

### 7. 打印与导出

列表行点「打印」进入打印预览页，顶部有「返回 / 导出 Word / 导出 PDF / 打印」四个按钮：

- **导出 Word**：下载 `单号.docx`，纯单据内容、A4 版式。
- **导出 PDF**：桌面版真正生成 PDF 文件；浏览器下可用「打印」选「另存为 PDF」。
- **打印**：调浏览器打印对话框。

打印/导出内容同源，包括：公司名称、地址、电话/传真、手机（如有）、标题「送 货 单」、客户名称/出货单号/出货日期、收货地址、明细表（序号、订单号码、品名、规格、单位、数量、单价、金额、备注，不足 6 行补空行）、整单备注、金额小计与中文大写金额、经营范围、制单人，以及送货单位与收货单位两处盖章栏。规格按每行自己货品所属品类动态渲染，多品类混装互不干扰。

## 五、对库存与财务的影响

- 新建、编辑、复制、删除草稿，**不影响库存**。
- **确认**：按关联货品扣减库存（`DELIVERY_CONSUME`），允许扣成负数，可能触发库存不足提醒。
- **打回**：冲销扣库流水（`DELIVERY_REVERSE`），库存还回原值。
- 送货单本身**不直接产生应收账款**。销售侧的应收账款在「对帐单」确认时产生；对帐单可以按客户和月份汇总已确认的送货单来生成。

库存采用流水账模型：当前库存是流水增量的累加，历史流水不可修改；打回通过新增一条反向流水实现，全程可追溯。

## 六、注意事项

1. 只有关联了货品且数量大于 0 的明细行才会在确认时扣库；不关联的行只作文字记录。
2. 库存允许扣成负数，系统仅做提醒、不阻止确认；请根据提醒及时补货或核对数量。
3. 单价和数量必须为非负数；金额由系统计算，不能手填。
4. 从报价单带入仅预填明细和客户，不自动带入收货地址，需自行填写。
5. 客户名称、规格字段名都是制单时的快照，之后修改客户档案或品类规格不会回写旧单。
6. 送货单号前缀来自公司基础信息，修改前缀只影响之后新建的单据，不改旧单。
7. 确认后的送货单不能编辑或删除，要修改只能打回后复制成新单。
8. 打印抬头、经营范围、制单人来自公司基础信息档案，若显示为空请先在「公司基础信息」补全。
