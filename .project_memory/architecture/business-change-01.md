# 业务变更 01 · 产品品类可自定义（已实现 2026-11-21）

> 主人拍板：允许新建模块、序号客户填、规格字段只允许增删（不改名/删已用字段）、有货品的品类禁止删除。
> 状态：后端 CRUD + 规格管理 + 删除保护 + schema 迁移 + 前端增删改页面全部完成，26 测试通过，旧库迁移实测通过。

> 日期 2026-11-21。主人需求原文：
> 「产品品类模块：应该支持客户自定义添加和删除不同的产品品类，其中序号、品类、模块字段保留，规格字段应该允许客户自定义添加」

## 1. 现状
- 品类是**只读的**：6 类（圆纸片/圆纸板/纸管/纸箱/塑料管芯/塑料圆卡）写死在 `seed.ts`，前端 CategoriesView 只能看。
- 表结构 `product_categories` 已有字段：`id, name(唯一), module, spec_schema(JSON), sort_order, created_at`——**不用改表**，只需开放 CRUD API + 前端增删改界面。
- 引用关系：
  - `products.category_id → categories.id`（无 CASCADE）
  - `supplier_categories.category_id → categories.id`（ON DELETE CASCADE）

## 2. 目标
- 客户可**新增 / 编辑 / 删除**品类。
- 保留字段：`序号(sort_order)`、`品类(name)`、`模块(module)`。
- **规格字段(spec_schema) 允许客户自定义添加**：即客户能给某个品类增减规格字段（字段名、显示名、类型、单位、是否预留）。

## 3. 方案

### 后端 · 品类 CRUD
- `POST /categories` 新增：`{name, module, sortOrder?, specSchema?}`
- `PATCH /categories/:id` 编辑（含规格字段）
- `DELETE /categories/:id` 删除
- `specSchema` 是一个字段数组，每个字段 `{key, label, type:'number'|'text', unit?, reserved?}`，整组替换存储。
- 校验：name 非空且唯一（已有 UNIQUE 约束，冲突返回 409）；模块值合法。

### 后端 · 规格字段自定义
- 规格字段走 `spec_schema` JSON 数组，客户可通过界面增删字段、改字段名/类型/单位。
- 字段的 `key` 存进货品 specs JSON；改 key 会导致已有货品该字段失联——需处理（见待确认 Q3）。

### 后端 · 删除保护
- 有货品引用的品类**禁止删除**（返回 409，提示"该品类下还有 N 个货品，请先处理"），避免货品变成孤儿。
- 供货商经营品类关联随删除自动清理（已有 CASCADE）。

### 后端 · 种子策略
- 6 类种子保留为**首次初始化的默认数据**（`INSERT OR IGNORE`，不覆盖客户改动）。首次装软件就有 6 类可用，客户可再增删改。已存在的库不受影响。

### 前端 · 品类页改造
- 从只读表格 → 可增删改：
  - 「+ 新增品类」按钮，弹表单：品类名称、模块、规格字段列表（可增删行：字段名/显示名/类型/单位）。
  - 每行品类加「编辑 / 删除」按钮。
  - 规格字段以标签形式展示。

## 4. 待主人确认（影响实现）
- **Q1 模块是否可自定义**：当前模块是枚举 `paper/plastic`（纸制品/塑料制品）。客户新增品类时，模块只能从这两个选，还是要能自定义新模块（如"金属制品"）？
  - 建议：**改成可自定义的模块表/字符串**，更灵活；但要动 CHECK 约束（需迁移）。
  - 若保持两分类简单，客户新增品类只能归到纸/塑料。
- **Q2 序号用途**：`sort_order` 只控制显示顺序，客户可在表单里填数字。是否接受？
- **Q3 改规格字段名**：若客户改了某个规格字段的 key，已录入货品的对应规格值会"失联"。处理方式：
  - (a) 禁止改已有字段的 key（只能新增/删除字段）——推荐，简单安全；
  - (b) 允许改，同时迁移所有货品 specs 里的旧 key→新 key。
- **Q4 删除品类时其下货品**：禁止删除（推荐，保护数据）还是连同货品一起删？

## 5. 影响面
- 改：categories 模块（service/controller/前端）、seed 注释、e2e 测试。
- 不改：货品/供货商/库存/报价单逻辑（品类作为字典被引用，CRUD 后自然生效）。
- 打包：改完需重新出安装包（新版本号或覆盖 release）。
